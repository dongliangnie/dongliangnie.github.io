KV Cache笔记

  2026-05-22    paper_notes  VLM/LLM  Inference    KV Cache

KV Cache 的由来

​ 在自回归生成（autoregressive generation）过程中，模型每次只生成一个 token，然后将这个 token 拼接到已有序列后面，再生成下一个 token。这个过程看似简单，但隐藏着巨大的计算冗余。

标准的多头自注意力（Multi-Head Self-Attention）计算如下：

Attention(Q,K,V)=softmax(QKTdk)V\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V Attention(Q,K,V)=softmax(dk​​QKT​)V

其中 QQQ、KKK、VVV 分别是查询（Query）、键（Key）和值（Value）矩阵，dkd_kdk​ 是每个注意力头的维度。

在训练阶段，由于有 causal mask（因果掩码），整个序列的 QQQ、KKK、VVV 可以并行计算。但在推理的自回归生成阶段，当我们生成第 ttt 个 token 时：

  • 新的 Query：只有当前第 ttt 个位置的查询向量 qt∈Rdkq_t \in \mathbb{R}^{d_k}qt​∈Rdk​
  • Key 和 Value：需要用到位置 111 到 ttt 所有 token 对应的 k1,k2,…,ktk_1, k_2, \ldots, k_tk1​,k2​,…,kt​ 和 v1,v2,…,vtv_1, v_2, \ldots, v_tv1​,v2​,…,vt​

关键问题在于：位置 111 到 t−1t-1t−1 的 KKK、VVV 向量在生成第 t−1t-1t−1 个 token 时就已经计算过了。如果不做任何缓存，每一步都要重新从头计算所有历史 token 的 KKK 和 VVV，这意味着生成第 ttt 个 token 的复杂度是 O(t)O(t)O(t)，整个序列生成的总复杂度是 O(n2)O(n^2)O(n2)，在长序列下极其低效。

KV Cache 的思路非常直观：把已经计算过的 Key 和 Value 向量缓存起来，下一步直接拿来用。这样每步生成只需要：

  1. 计算当前 token 的 qtq_tqt​、ktk_tkt​、vtv_tvt​
  2. 把 ktk_tkt​、vtv_tvt​ 追加到缓存
  3. 用 qtq_tqt​ 与缓存中所有 KKK、VVV 做注意力计算

每步的注意力计算复杂度从 O(t⋅d)O(t \cdot d)O(t⋅d) 的完整重计算降到了 O(1)O(1)O(1)（对于 QQQ 的计算部分），极大地提升了推理效率。

KV Cache 到底缓存了什么？

单层、单头的 KV Cache

对于 Transformer 的第 lll 层，第 hhh 个注意力头，输入 token 序列 x1,x2,…,xt∈Rdmodelx_1, x_2, \ldots, x_t \in \mathbb{R}^{d_{model}}x1​,x2​,…,xt​∈Rdmodel​，对应的 Key 和 Value 通过线性投影得到：

ki(l,h)=xiWK(l,h),vi(l,h)=xiWV(l,h)k_i^{(l,h)} = x_i W_K^{(l,h)}, \quad v_i^{(l,h)} = x_i W_V^{(l,h)} ki(l,h)​=xi​WK(l,h)​,vi(l,h)​=xi​WV(l,h)​

其中 WK(l,h),WV(l,h)∈Rdmodel×dkW_K^{(l,h)}, W_V^{(l,h)} \in \mathbb{R}^{d_{model} \times d_k}WK(l,h)​,WV(l,h)​∈Rdmodel​×dk​，dk=dmodel/Hd_k = d_{model} / Hdk​=dmodel​/H（HHH 是注意力头数）。

第 lll 层、第 hhh 头的 KV Cache，在处理完前 ttt 个 token 后，存储的是：

KV Cache(l,h)=([k1(l,h)k2(l,h)⋮kt(l,h)],[v1(l,h)v2(l,h)⋮vt(l,h)])\text{KV Cache}^{(l,h)} = \left(\begin{bmatrix}k_1^{(l,h)} \\ k_2^{(l,h)} \\ \vdots \\ k_t^{(l,h)}\end{bmatrix}, \begin{bmatrix}v_1^{(l,h)} \\ v_2^{(l,h)} \\ \vdots \\ v_t^{(l,h)}\end{bmatrix}\right) KV Cache(l,h)=⎝⎜⎜⎜⎜⎜⎛​⎣⎢⎢⎢⎢⎢⎡​k1(l,h)​k2(l,h)​⋮kt(l,h)​​⎦⎥⎥⎥⎥⎥⎤​,⎣⎢⎢⎢⎢⎢⎡​v1(l,h)​v2(l,h)​⋮vt(l,h)​​⎦⎥⎥⎥⎥⎥⎤​⎠⎟⎟⎟⎟⎟⎞​

形状均为 Rt×dk\mathbb{R}^{t \times d_k}Rt×dk​。

整个模型的 KV Cache

设模型有 LLL 层、HHH 个头、头维度为 dkd_kdk​，当前序列长度为 ttt，则完整的 KV Cache 包含：

  • KKK 的缓存：L×HL \times HL×H 个矩阵，每个形状为 t×dkt \times d_kt×dk​
  • VVV 的缓存：L×HL \times HL×H 个矩阵，每个形状为 t×dkt \times d_kt×dk​

通常在实现中，会把 HHH 个头合并，所以每层的 KV Cache 形状为：

K-cachel:Rt×H×dk,V-cachel:Rt×H×dkK\text{-cache}_l: \mathbb{R}^{t \times H \times d_k}, \quad V\text{-cache}_l: \mathbb{R}^{t \times H \times d_k} K-cachel​:Rt×H×dk​,V-cachel​:Rt×H×dk​

总参数量：2×L×t×H×dk=2×L×t×dmodel2 \times L \times t \times H \times d_k = 2 \times L \times t \times d_{model}2×L×t×H×dk​=2×L×t×dmodel​

KV Cache 的大小与序列长度 ttt 成线性关系，与模型宽度（dmodeld_{model}dmodel​）成线性关系，与层数 LLL 成线性关系。这三个因素叠加，会让 KV Cache 在大模型、长序列场景下变得非常庞大。

为什么不缓存 Query？

这是一个值得思考的问题。理论上 Query 也可以缓存，但没有意义：

  • 在生成第 ttt 步时，我们只需要当前 token 的 qtq_tqt​ 来做注意力查询
  • 历史位置 1,…,t−11, \ldots, t-11,…,t−1 的 Query 在当前步骤中不会再被用到（因果注意力只向前看）
  • Query 不参与后续步骤的计算，缓存它只会浪费内存

Key 和 Value 则不同：每次生成新 token，当前的 qtq_tqt​ 都需要与所有历史 token 的 ki,vik_i, v_iki​,vi​ 做注意力，所以缓存 KKK、VVV 是有实际收益的。

内存占用：为什么 KV Cache 会成为瓶颈

量化计算

我们以 LLaMA-2 70B 为例，做一个具体的内存占用计算：

参数 值
层数 L 80
注意力头数 H 64
KV 头数（GQA） 8
头维度 d_k 128
精度 FP16（2 bytes）

对于标准 MHA（Multi-Head Attention），序列长度为 ttt 时单条请求的 KV Cache 大小：

Size=2×L×H×dk×t×bytes_per_element\text{Size} = 2 \times L \times H \times d_k \times t \times \text{bytes\_per\_element} Size=2×L×H×dk​×t×bytes_per_element

=2×80×64×128×t×2 bytes= 2 \times 80 \times 64 \times 128 \times t \times 2 \text{ bytes} =2×80×64×128×t×2 bytes

=2×80×64×128×2×t bytes= 2 \times 80 \times 64 \times 128 \times 2 \times t \text{ bytes} =2×80×64×128×2×t bytes

=2621440×t bytes≈2.5 MB/token= 2621440 \times t \text{ bytes} \approx 2.5 \text{ MB/token} =2621440×t bytes≈2.5 MB/token

当序列长度为 4096 token 时：2.5 MB×4096≈10 GB2.5 \text{ MB} \times 4096 \approx 10 \text{ GB}2.5 MB×4096≈10 GB

而 LLaMA-2 70B 模型权重本身（FP16）约为 140 GB。这意味着：

  • 单条长序列请求的 KV Cache 就可能占用几十 GB 显存
  • 批量并发时（batch_size=32），KV Cache 可超过模型权重本身

KV Cache 的动态性问题

与模型权重不同，KV Cache 有几个让它格外难处理的特点：

动态增长：每生成一个 token，KV Cache 就增长一块。这意味着很难在请求开始前就为它分配好内存。

请求间差异巨大：不同请求可能生成 10 个 token，也可能生成 10000 个 token。如果按最大长度预分配，内存浪费严重；如果动态分配，又容易产生碎片。

批处理复杂性：在一个 batch 中，不同请求处于不同的生成阶段，KV Cache 长度各不相同，难以高效地打包成规则张量。

这些问题在 vLLM 论文中有详细分析，实验数据显示，在朴素实现下，KV Cache 内存碎片导致的浪费可以高达 60-80% 的可用显存。

推理阶段的两个瓶颈

LLM 推理通常分为两个阶段：

  • Prefill（预填充）阶段：并行处理输入 prompt，一次性计算所有输入 token 的 KV，填充 KV Cache。这个阶段是计算密集型（compute-bound）。
  • Decode（解码）阶段：逐 token 生成，每步只处理一个 token，但需要读取全部 KV Cache。这个阶段是内存带宽密集型（memory-bound）。

在 Decode 阶段，GPU 的算力（FLOPS）大部分是空闲的，瓶颈在于把 KV Cache 从显存搬到计算单元的带宽。这就是为什么优化 KV Cache 的内存布局和访问模式，比单纯提升算力更重要。

从源头减少 KV 头的数量

PagedAttention 解决了”如何高效管理 KV Cache”的工程问题，而 MQA 和 GQA 则从模型架构层面解决”如何从根本上减少需要缓存的数据量”。

Multi-Head Attention（MHA）的冗余性

标准 MHA 中，每个注意力头都有独立的 WQhW_Q^hWQh​、WKhW_K^hWKh​、WVhW_V^hWVh​ 投影矩阵。实验观察发现：不同注意力头的 Key 和 Value 矩阵之间存在大量冗余，尤其是 Key 和 Value，而 Query 的多样性则更为重要（不同头的 Query 关注不同的语义模式）。

Multi-Query Attention（MQA）

MQA 由 Noam Shazeer 于 2019 年提出，思路极其简单粗暴：所有 Query 头共享同一组 Key 和 Value。

数学表达：

MHA:Qh=xWQh, Kh=xWKh, Vh=xWVh∀h∈[1,H]\text{MHA}: Q_h = xW_Q^h,\ K_h = xW_K^h,\ V_h = xW_V^h \quad \forall h \in [1, H] MHA:Qh​=xWQh​, Kh​=xWKh​, Vh​=xWVh​∀h∈[1,H]

MQA:Qh=xWQh, K=xWK, V=xWV（K, V 只有一组）\text{MQA}: Q_h = xW_Q^h,\ K = xW_K,\ V = xW_V \quad \text{（K, V 只有一组）} MQA:Qh​=xWQh​, K=xWK​, V=xWV​（K, V 只有一组）

KV Cache 的变化：

  • MHA：每层 KV Cache 大小 =2×t×H×dk= 2 \times t \times H \times d_k=2×t×H×dk​
  • MQA：每层 KV Cache 大小 =2×t×1×dk= 2 \times t \times 1 \times d_k=2×t×1×dk​（节省 HHH 倍）

以 LLaMA-2 70B 为例（H=64H=64H=64），MQA 理论上可以将 KV Cache 缩小到 MHA 的 1/641/641/64。

但 MQA 的代价是模型质量的下降。多个研究表明，MQA 在需要细粒度注意力的任务（如长文档理解、复杂推理）上表现明显弱于 MHA。

Grouped-Query Attention（GQA）

GQA 是 MHA 和 MQA 的折中方案，由 Ainslie et al. 于 2023 年提出。它将 HHH 个 Query 头分成 GGG 组，每组共享一对 K/V：

GQA:Qh=xWQh, Kg=xWKg, Vg=xWVg\text{GQA}: Q_h = xW_Q^h,\ K_g = xW_K^g,\ V_g = xW_V^g GQA:Qh​=xWQh​, Kg​=xWKg​, Vg​=xWVg​

其中 g=⌈h/(H/G)⌉g = \lceil h / (H/G) \rceilg=⌈h/(H/G)⌉，即第 hhh 个 Query 头属于第 ggg 组，使用该组的 Kg,VgK_g, V_gKg​,Vg​。

KV Cache 大小（每层）：

GQA:2×t×G×dk\text{GQA}: 2 \times t \times G \times d_k GQA:2×t×G×dk​

当 G=HG=HG=H 时退化为 MHA，当 G=1G=1G=1 时退化为 MQA。

关键实验数据：

模型架构 KV Cache 大小（相对MHA） 推理速度（相对MHA） 模型质量损失
MHA 1x 1x（基准） 无
GQA(G=8) 1/8x ~1.5-2x 几乎可忽略
MQA 1/H x 最快 明显

GQA 在 LLaMA-2、Mistral、Gemma 等主流开源模型中被广泛采用，其中 LLaMA-2 70B 使用 H=64,G=8H=64, G=8H=64,G=8，即 KV 头数只有 8，相比 MHA 节省了 8 倍 KV Cache。
